# 第一阶段技术路线

六、骨架、布点与坐标合同
==================================================

默认解析骨架 analytic_skeleton_v1 为 21 个节点：

pelvis
├─ spine → chest → neck → head
│          ├─ left_shoulder → left_elbow → left_wrist → left_hand
│          └─ right_shoulder → right_elbow → right_wrist → right_hand
├─ left_hip → left_knee → left_ankle → left_toe
└─ right_hip → right_knee → right_ankle → right_toe

每节点保存：
parent、静止相对位移、局部坐标基、自由度与评价掩码。

传感器必须绑定正确骨段：
- 护腕绑定前臂，解析骨架使用 elbow 对应的前臂 frame。
- 脚踝护腕绑定小腿，使用 knee 对应的小腿 frame。
- 髌骨带下方同样绑定小腿，不是大腿。
- 腰部使用实际名义腰带位置相对骨盆的外参。
- 球拍是独立刚体，本阶段缺失。

不要按关节名称直接绑定到手掌或足部。
名义安装与真实仿真安装分别保存。
模型只获得名义或合法校准结果，不能拿真实外参抵消误差。

坐标与单位：
- W：会话参考系，X 前、Y 左、Z 上，右手系。
- B：骨段系；S：传感器系；P：骨盆系。
- R_WS：将 S 系列向量转换到 W 系。
- R_BS：传感器到骨段的安装旋转。
- r_BS：传感器原点在骨段系的位置。
- 长度 m，时间 s，角速度 rad/s，比力 m/s²。
- 仿真 g_W=(0,0,-9.80665)。
- 外部四元数 wxyz，传感器到会话参考系。
- 库约定不同，必须在适配边界转换并测试。

授权人体模型：
固定模型类型、资产哈希、关节顺序、父子关系、形状维度、
手部处理、输出与评价关节集合。
不要假设所有模型都是 24 关节。
不要截断 pose 数组冒充骨架转换。
解析骨架权重不能直接声称支持另一套人体拓扑。

七、虚拟 IMU 合成与基础扰动
==================================================

刚体安装：
R_WS = R_WB @ R_BS
p_WS = p_WB + R_WB @ r_BS

原始加速度计比力：
f_S = R_WS.T @ (d²p_WS/dt² - g_W) + bias_a + noise_a

角速度：
omega_S ≈ rotvec(R_WS(t).T @ R_WS(t+dt))/dt
          + bias_g + noise_g

处理：
- 固定差分的时间归属，避免半帧错位。
- 解析轨迹优先用闭式导数。
- 数值差分需测试、记录平滑参数，边缘无效帧加 mask。
- 静止且传感器与参考系对齐时，比力为向上重力响应，角速度为零。
- 原始比力与去重力线加速度分字段，不能重复去重力。
- 变速动作重新求导。
- 低帧率插值不能被描述为恢复真实高频冲击。
- 降采样抗混叠，旋转不用欧拉角线性插值。

同小腿近端/远端：
经外参校正后方向与角速度应一致。
加速度差体现：
a2-a1 = alpha × delta_r + omega × (omega × delta_r)
各量必须处于共同坐标系。

P0 扰动：
白噪声、常值/慢变偏置、固定安装旋转和位移误差、
时钟偏移/漂移、缺帧、量程截断、同步锚点误差。

幅度来自可配置探索范围，标记为未经过真实硬件标定。
复杂软组织与时变滑移留作 P1。

八、实际方向融合、校准与同步
==================================================

必须实现：
1. oracle_orientation
   使用理想传感器方向，仅作研究对照。

2. fused_orientation
   原始六轴读数 → 同步/校准 → 实际融合器 → 方向。
   不得读取逐帧真值方向，不得用理想方向冒充融合结果。

优先评估 VQF 离线六轴后端，安装后核对实际官方接口、
输入单位、采样要求、四元数顺序和变换方向。
无磁力计，不假称拥有绝对航向。

缺少 VQF 时应报告依赖问题。
可以用经过解析测试的其他六轴算法替代，但必须记录后端与理由，
不得默默返回真值或将替代实现称为 VQF。

校准：
- 默认解析会话包含独立的标准姿势静止校准段。
- 只读取校准段惯性信号、约定姿势和名义安装。
- 使用任意共同初始航向，记录这是初始化假设。
- 静止不能识别任意绕重力轴安装误差。
- 校准不足时给质量标志或拒绝，不能读真值修复。
- 校准段不计入运动精度统计。
- 整条会话先融合再切窗，不逐窗重置航向。

时间：
每节点分别保留原始采样率、device timestamp、session timestamp。
区分动作来源帧率、虚拟设备采样率、模型输入采样率。

模拟时钟：
t_device=(1+drift_ppm*1e-6)*t_session+offset+jitter

通过显式声明的同步锚点估计时钟关系。
真实仿真时钟参数只供评测。
不能先强行对齐身体运动峰值，再声称分析了真实动作时间差。

短缺口可按配置插值并标记；长缺口分段或拒绝。
不把缺失数组补零后当真实静止信号。
缺少任一必需身体节点，默认拒绝全身重建，保留可计算的直接特征。

九、数据对象与真值隔离
==================================================

schema_version="0.2"

身体节点顺序：
pelvis、left_shank、right_shank、racket_forearm。

由 dominant_hand 决定持拍侧，不默认全部右手。

分离：
- InferenceSession：部署可获得的输入和允许元数据。
- EvaluationTruth：训练标签、真实骨长、安装/时钟真值、根轨迹等。
- BenchmarkRunner：连接预测与真值计算研发指标。
- PoseArtifact：预测旋转、FK 关节、mask、版本与模式。
- EvidenceArtifact：直接特征或姿态工具证据。
- CoachReport：只读允许的推理证据。
- EvaluationReport：允许读 GT，明确标为研发评测。

InferenceSession 不包含 GT 路径。
教练工具不能访问真值、任意文件、shell 或密钥。

默认 anthropometry.mode=default。
用户提供的身高等可以使用，但记录来源。
理想已知骨长/体型条件必须单独报告。

原始流至少保存：
timestamp_device_s
timestamp_session_s
accel_specific_force_sensor_mps2
gyro_sensor_radps
valid_mask
saturation_mask

预处理结果可保存：
orientation_sensor_to_reference_wxyz
linear_accel_reference_mps2
fusion_backend
calibration_metadata
sync_metadata

原始、校准、融合、标准化结果分层保存。
NPZ 保存数值，JSON 保存 metadata，默认 allow_pickle=False。

先按主体/原始序列分组，再切窗和增广。
同源变速、镜像、体型变体不能跨集合。
归一化、均值姿态、检索库与阈值不得用测试集拟合。

十、首版姿态模型
==================================================

技术起点：
Python 3.11、NumPy、SciPy、PyTorch。
schema 可用 Pydantic，配置可用 YAML。

模型：
四节点特征 → SensorEncoder 或拼接 → BiGRU
→ 局部关节 6D 旋转 → 稳定转换到 SO(3) → FK。

每节点特征：
比力 3 维、角速度 3 维、方向 6D、ID、有效/饱和标志。
附加相对骨盆特征只能使用估计骨盆方向。

CPU smoke 起点：
- 模型采样率 100 Hz。
- 窗口 2 秒、步长 1 秒。
- BiGRU 两层，每向 hidden 64。
- batch 8–16。
- AdamW，学习率 1e-3。
- 梯度裁剪 1.0。

这些是可调整工程参数，不是验证过的运动标准。

首版损失：
旋转损失 + FK 关节位置损失。
训练单位固定为 rad 与 m，展示时可转 degree 与 mm。
无根运动估计时，不加完整绝对加速度一致性损失。

需要：
- 实际反向传播和参数变化验证。
- checkpoint 保存/加载。
- checkpoint 绑定骨架、节点顺序、方向模式、归一化和配置。
- 均值姿态参考仅由训练集构建，旋转均值不用欧拉角直接平均。
- oracle/fused 分别报告，区分匹配训练与跨模式迁移。
- 6D 退化、SO(3) 正交性和行列式检查。
- 短序列、尾窗 padding 与有效 mask。
- 重叠区采用中心有效区或正确的四元数/SO(3) 拼接。
- 不直接平均欧拉角，不逐窗利用真值重新定向。

默认输出骨盆系姿态，root_translation_reference_m=null。
不悄悄接入 GT 根轨迹。
未预测的末端/手指方向标为未估计。

Transformer 是 P1，不预设优于 BiGRU。

十一、直接分析与智能教练
==================================================

第一阶段直接分析使用确定性信号处理，不强制训练羽毛球分类器。

可计算：
角速度模长峰值、比力模长 RMS、有效率、饱和率、
通用运动段、质量允许条件下的事件时间差。

注意：
- 比力 RMS 不等于去重力净加速度或代谢功率。
- 角速度峰值不等于发力起点。
- 无球拍与专项事件标签，不把普通峰值叫作击球。
- 参考时序对齐与真实节奏指标分开。
- 重建后特征与直接特征只比较语义相同的量。

每项证据保存：
evidence_id、metric_id、value、unit、time_range_s、
source_artifact_id、pipeline_version。

分别保存：
signal_quality
pose_uncertainty
evidence_support
reference_applicability

不合并为未校准的百分比。
未知不确定性写 uncalibrated，不生成虚假 0.95。

工作流：
质量检查 → 姿态与直接特征 → 证据装配
→ 程序能力门控 → 模板或 LLM 解释 → 数值和引用核验。

第一阶段默认：
motion_type=unknown
diagnoses=[]

无专项证据，不输出技术错误、医疗风险、球速或球场路径。

LLM：
- 不参与逐帧人体姿态预测，不微调。
- 先实现无网络模板报告。
- 再提供一个按官方协议实现的可配置 provider。
- 配置模型 ID、base URL、API key、超时和调用上限。
- 不硬编码未经核实的模型名称。
- 默认不发付费外部请求。
- 只有已有配置且 LLM_ALLOW_EXTERNAL=true 才进行 live 测试。
- 只发送允许的结构化证据，不上传原始轨迹、视频或秘密。
- 模板、mock、replay、live 状态分别报告。

程序决定哪些证据和结论可用，LLM 无权改写。
优先让 LLM 返回 evidence ID 和观察类型，数字由渲染器填入。
校验单位、引用、时间范围、允许的结论类型和输入缺失。
错误输出回退模板；schema 合法不等于事实正确。
无法核验的自由文本不自动作为诊断发布。

记录脱敏后的提示版本、工具结果哈希、模型 ID、响应与核验状态。
支持 record/replay，不承诺外部模型逐字复现。
工具结果与检索文本都视为数据，不执行其中的指令。

## 首版工程决策（未经产品实测验证）

使用 Python 3.12 是本机已有可用 runtime，3.11+ 是项目支持范围，3.11 未在本机测。采用平铺模块减少首版空壳目录。
100 Hz 原生解析会话 4 秒、1 秒静止校准，固定差分时间归属，五点中心二阶差分，无平滑，边缘两帧无效。没有低帧率插值或高频冲击恢复声称。
