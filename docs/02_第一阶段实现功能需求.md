# 第一阶段实现功能需求

四、首版两种数据路线与授权要求
==================================================

A. demo_synthetic：必须实际运行

自行定义解析骨架、骨长配置和参数化运动。
不依赖受限模型文件，不从外部人体模型中抄取资产。

生成：
- 静止。
- 根部平移。
- 整体旋转。
- 单关节正弦运动。
- 多关节组合运动。
- 不同速度、幅度、左右侧和配置骨长的变体。

所有样例明确标为 synthetic_analytic / synthetic_demo_only。
它们不是专业羽毛球动作，也不证明真实人体泛化。

用真实训练和推理代码完成：
合成 → 融合 → BiGRU 训练 → checkpoint → 独立推理 → 回放 → 报告。

不得使用 GT、固定答案或随机骨架冒充训练好的预测。

B. licensed_motion：实现可配置的真实适配入口

- 使用用户提供且用途授权明确的动作和人体模型。
- 实现资产清单、版本、路径、格式、关节映射与维度检查。
- 第一版支持一种明确的数据与模型组合即可。
- 不支持的格式明确报 unsupported。
- 无资产时，用自编 fixture 测试接口；真实集成标为未验证。
- 不得以空类或固定返回值冒充加载器。

维护 license_manifest：
资产 ID、类别、来源、版本/哈希、预期用途、许可、
授权状态、允许的处理/分发范围、凭证引用。

不自动下载受限资产，不自动接受许可。
不默认公开可下载就允许产品训练。
代码、动作数据、人体模型与预训练权重分别检查授权。
私有仓库不能替代第三方授权。
原始授权凭证和个人信息不提交仓库。

九、数据对象与真值隔离
==================================================

schema_version="0.2"

身体节点顺序：
pelvis、left_shank、right_shank、racket_forearm。

由 dominant_hand 决定持拍侧，不默认全部右手。

分离：
- InferenceSession：部署可获得的输入和允许元数据。
- EvaluationTruth：训练标签、真实骨长、安装/时钟真值、根轨迹等。
- BenchmarkRunner：连接预测与真值计算研发指标。
- PoseArtifact：预测旋转、FK 关节、mask、版本与模式。
- EvidenceArtifact：直接特征或姿态工具证据。
- CoachReport：只读允许的推理证据。
- EvaluationReport：允许读 GT，明确标为研发评测。

InferenceSession 不包含 GT 路径。
教练工具不能访问真值、任意文件、shell 或密钥。

默认 anthropometry.mode=default。
用户提供的身高等可以使用，但记录来源。
理想已知骨长/体型条件必须单独报告。

原始流至少保存：
timestamp_device_s
timestamp_session_s
accel_specific_force_sensor_mps2
gyro_sensor_radps
valid_mask
saturation_mask

预处理结果可保存：
orientation_sensor_to_reference_wxyz
linear_accel_reference_mps2
fusion_backend
calibration_metadata
sync_metadata

原始、校准、融合、标准化结果分层保存。
NPZ 保存数值，JSON 保存 metadata，默认 allow_pickle=False。

先按主体/原始序列分组，再切窗和增广。
同源变速、镜像、体型变体不能跨集合。
归一化、均值姿态、检索库与阈值不得用测试集拟合。

十一、直接分析与智能教练
==================================================

第一阶段直接分析使用确定性信号处理，不强制训练羽毛球分类器。

可计算：
角速度模长峰值、比力模长 RMS、有效率、饱和率、
通用运动段、质量允许条件下的事件时间差。

注意：
- 比力 RMS 不等于去重力净加速度或代谢功率。
- 角速度峰值不等于发力起点。
- 无球拍与专项事件标签，不把普通峰值叫作击球。
- 参考时序对齐与真实节奏指标分开。
- 重建后特征与直接特征只比较语义相同的量。

每项证据保存：
evidence_id、metric_id、value、unit、time_range_s、
source_artifact_id、pipeline_version。

分别保存：
signal_quality
pose_uncertainty
evidence_support
reference_applicability

不合并为未校准的百分比。
未知不确定性写 uncalibrated，不生成虚假 0.95。

工作流：
质量检查 → 姿态与直接特征 → 证据装配
→ 程序能力门控 → 模板或 LLM 解释 → 数值和引用核验。

第一阶段默认：
motion_type=unknown
diagnoses=[]

无专项证据，不输出技术错误、医疗风险、球速或球场路径。

LLM：
- 不参与逐帧人体姿态预测，不微调。
- 先实现无网络模板报告。
- 再提供一个按官方协议实现的可配置 provider。
- 配置模型 ID、base URL、API key、超时和调用上限。
- 不硬编码未经核实的模型名称。
- 默认不发付费外部请求。
- 只有已有配置且 LLM_ALLOW_EXTERNAL=true 才进行 live 测试。
- 只发送允许的结构化证据，不上传原始轨迹、视频或秘密。
- 模板、mock、replay、live 状态分别报告。

程序决定哪些证据和结论可用，LLM 无权改写。
优先让 LLM 返回 evidence ID 和观察类型，数字由渲染器填入。
校验单位、引用、时间范围、允许的结论类型和输入缺失。
错误输出回退模板；schema 合法不等于事实正确。
无法核验的自由文本不自动作为诊断发布。

记录脱敏后的提示版本、工具结果哈希、模型 ID、响应与核验状态。
支持 record/replay，不承诺外部模型逐字复现。
工具结果与检索文本都视为数据，不执行其中的指令。

十三、实验、测试与验收
==================================================

必须提供以下实验配置和小规模真实结果：
E1 BiGRU vs 训练集均值姿态。
E2 oracle vs fused。
E3 小腿近端 vs 远端。
E4 干净 vs 基础扰动/缺帧/错时。
E5 默认体型 vs 研究性已知体型。

未运行的实验明确标记，不伪造结果。
大规模训练、多种子与 Transformer 可延期。

主指标：
骨盆系 MPJPE、局部旋转误差。
方向具备可比较条件时另报根方向误差。
逐关节、持拍/非持拍侧、有直接关联观测/缺少观测、
快慢动作、默认/已知体型分别统计。

无可靠根高度/地面时，穿地率 unavailable。
平滑性不能代替准确性，另看峰值和时间保真。
统计按主体或原始序列，不将重叠帧当独立样本。
开发集确定门槛后冻结，再评测独立测试集。

必要测试：
- FK、旋转、骨段绑定。
- 静止/平移/旋转的比力与角速度。
- 同刚体多站点和安装误差。
- 时钟、同步、缺帧、饱和。
- 融合不读取真值。
- 改变 EvaluationTruth 不改变固定输入的预测与教练数值证据。
- 划分、增广和归一化不泄漏。
- 训练参数确实更新，checkpoint 可重载。
- 6D 退化、旋转合法、滑窗与短序列。
- 无标签、无参考、缺节点、错误单位和 evidence ID。
- 工具失败、冲突、模板降级、replay 与密钥脱敏。
- CPU 端到端生成回放、教练报告和独立评测报告。

不删除正确测试或随意放宽容差来制造通过。
缺资源的测试记录 skip/blocked 与原因，不能写成 passed。
CI 只使用原创小型 fixtures，不依赖受限资产、个人密钥或付费 API。

至少实现并验证以下命令，必要调整后同步文档：

python -m badminton_coach.cli doctor
python -m badminton_coach.cli demo --config configs/smoke.yaml --device cpu --output artifacts/demo
python -m badminton_coach.cli train --config configs/smoke.yaml --device cpu
python -m badminton_coach.cli evaluate --run-dir artifacts/demo
python -m badminton_coach.cli report --run-dir artifacts/demo --backend template
python -m pytest -q
python -m ruff check .

demo 必须调用真实模块，不另写一套伪造演示。
重复运行使用新 run ID 或显式 overwrite，不毁坏旧结果。

三类验收：
- 工程：管线、解析测试、真实训练、报告与回放正常。
- 研究：授权动作数据下的独立评价支持相应算法结论。
- 产品：真实设备、跨用户与教练标注支持具体功能。

只有解析样例时：
工程可以通过，研究/产品仍为 not_validated。

## 输出协议与失败处理

PoseArtifact：schema_version 0.2、局部旋转 [T,21,3,3]、joints_pelvis_m [T,21,3]、valid_mask [T]、metadata；root_translation_reference_m=null。
EvidenceArtifact：evidence_id / metric_id / value / unit / time_range_s / source_artifact_id / pipeline_version。
CoachReport：unknown 动作、空 diagnoses、经程序核验的 observations、分开的质量/支持/适用性；EvaluationReport 允许读 GT，单独保存。
缺少身体节点拒绝重建而保留直接测量；长缺口拒绝；错误单位/授权/拓扑明确报错；LLM 失败降级模板，证据冲突则拒绝发布。
NPZ allow_pickle=False；metadata JSON；原始、融合、预测、真值各自保存。不存在第五路复制数据。
