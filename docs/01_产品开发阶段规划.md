# 产品开发阶段规划

二、产品目标与固定约束
==================================================

产品目标：
利用少量可穿戴 IMU，在运动结束后离线分析，生成估计的三维人体动作回放，
并结合直接惯性特征、姿态运动学和受证据约束的智能体给出反馈。

最终最多五个节点：

- pelvis：腰部裤带夹扣或纽扣式设备。
- left_shank：左侧小腿，髌骨带下方或脚踝护腕。
- right_shank：右侧小腿，髌骨带下方或脚踝护腕。
- racket_forearm：持拍侧前臂远端，手表或护腕。
- racket：球拍手柄底盖。

关键约束：
- 最终是四个身体节点加一个球拍节点。
- 不追加胸带、上臂或大腿节点作为用户使用前提。
- 不把手机作为额外 IMU，不要求放在球场地面。
- 不强制用户拍摄视频。
- 不要求实时重建。
- 研发阶段可用更多参考设备，但这些数据不得混入产品推理输入。

第一阶段只有四身体节点有效：
pelvis、left_shank、right_shank、racket_forearm。

球拍节点：
racket=null
racket_present=false

不得把前臂数据复制为球拍数据。

能力边界：
- 第一阶段输出骨盆参考系下的相对人体姿态。
- 不承诺恢复球场绝对位置、长时间移动轨迹或可靠根高度。
- 不把骨盆方向称为胸部或躯干方向。
- 不把前臂角速度称为腕关节角速度。
- 不把球拍角速度称为拍头线速度或羽毛球速度。
- 不承诺精确膝角、膝内扣、关节载荷或医学伤害风险。
- 没有专项标签和验证时，只描述观察或差异，不认定技术错误。
- 动画自然不等于重建准确。
- 姿态和直接 IMU 两条分析通路同源，不能当作独立验证。

三、产品开发阶段
==================================================

阶段 I：四身体 IMU 仿真工程与研究原型
- 完成测量定义、骨段绑定、原始 IMU 合成、实际方向融合。
- 首版 BiGRU + FK。
- 相对姿态回放、直接特征、程序门控、模板报告和 LLM 接口。
- 预留球拍节点，不伪造第五路观测。
- 区分工程可运行与算法研究有效。

阶段 II：羽毛球专项数据与球拍
- 接入授权明确的人体及球拍同步轨迹。
- 加入球拍刚体模型及手部相对运动。
- 低频轨迹合成与击球冲击/振动建模分开。
- 有可靠标签后训练动作分类、击球事件和步法识别。
- 专业技术错误标签需要教练审核。
- 比较四身体与四身体加球拍的增益。

阶段 III：真实硬件与 Sim-to-Real
- 验证安装、量程、时钟、缓存、融合和佩戴扰动。
- 用多视角视频或参考动捕开展研发验证。
- 验证不同用户、惯用手、体型与场地。
- 必要时重训练、微调、校准不确定性或限制能力。
- 阶段 I 后半段或阶段 II 可提前做少量真实信号核验；
  不强制第一阶段购买完整硬件。

阶段 IV：产品化
- 小型化、续航、耐汗耐冲击、移动端、隐私、升级与成本控制。
- 每种新增诊断能力单独验证后开放。

四、首版两种数据路线与授权要求
==================================================

A. demo_synthetic：必须实际运行

自行定义解析骨架、骨长配置和参数化运动。
不依赖受限模型文件，不从外部人体模型中抄取资产。

生成：
- 静止。
- 根部平移。
- 整体旋转。
- 单关节正弦运动。
- 多关节组合运动。
- 不同速度、幅度、左右侧和配置骨长的变体。

所有样例明确标为 synthetic_analytic / synthetic_demo_only。
它们不是专业羽毛球动作，也不证明真实人体泛化。

用真实训练和推理代码完成：
合成 → 融合 → BiGRU 训练 → checkpoint → 独立推理 → 回放 → 报告。

不得使用 GT、固定答案或随机骨架冒充训练好的预测。

B. licensed_motion：实现可配置的真实适配入口

- 使用用户提供且用途授权明确的动作和人体模型。
- 实现资产清单、版本、路径、格式、关节映射与维度检查。
- 第一版支持一种明确的数据与模型组合即可。
- 不支持的格式明确报 unsupported。
- 无资产时，用自编 fixture 测试接口；真实集成标为未验证。
- 不得以空类或固定返回值冒充加载器。

维护 license_manifest：
资产 ID、类别、来源、版本/哈希、预期用途、许可、
授权状态、允许的处理/分发范围、凭证引用。

不自动下载受限资产，不自动接受许可。
不默认公开可下载就允许产品训练。
代码、动作数据、人体模型与预训练权重分别检查授权。
私有仓库不能替代第三方授权。
原始授权凭证和个人信息不提交仓库。

十三、实验、测试与验收
==================================================

必须提供以下实验配置和小规模真实结果：
E1 BiGRU vs 训练集均值姿态。
E2 oracle vs fused。
E3 小腿近端 vs 远端。
E4 干净 vs 基础扰动/缺帧/错时。
E5 默认体型 vs 研究性已知体型。
E6 直接信号 vs 重建后语义相同特征。

未运行的实验明确标记，不伪造结果。
大规模训练、多种子与 Transformer 可延期。

主指标：
骨盆系 MPJPE、局部旋转误差。
方向具备可比较条件时另报根方向误差。
逐关节、持拍/非持拍侧、有直接关联观测/缺少观测、
快慢动作、默认/已知体型分别统计。

无可靠根高度/地面时，穿地率 unavailable。
平滑性不能代替准确性，另看峰值和时间保真。
统计按主体或原始序列，不将重叠帧当独立样本。
开发集确定门槛后冻结，再评测独立测试集。

必要测试：
- FK、旋转、骨段绑定。
- 静止/平移/旋转的比力与角速度。
- 同刚体多站点和安装误差。
- 时钟、同步、缺帧、饱和。
- 融合不读取真值。
- 改变 EvaluationTruth 不改变固定输入的预测与教练数值证据。
- 划分、增广和归一化不泄漏。
- 训练参数确实更新，checkpoint 可重载。
- 6D 退化、旋转合法、滑窗与短序列。
- 无标签、无参考、缺节点、错误单位和 evidence ID。
- 工具失败、冲突、模板降级、replay 与密钥脱敏。
- CPU 端到端生成回放、教练报告和独立评测报告。

不删除正确测试或随意放宽容差来制造通过。
缺资源的测试记录 skip/blocked 与原因，不能写成 passed。
CI 只使用原创小型 fixtures，不依赖受限资产、个人密钥或付费 API。

至少实现并验证以下命令，必要调整后同步文档：

python -m badminton_coach.cli doctor
python -m badminton_coach.cli demo --config configs/smoke.yaml --device cpu --output artifacts/demo
python -m badminton_coach.cli train --config configs/smoke.yaml --device cpu
python -m badminton_coach.cli evaluate --run-dir artifacts/demo
python -m badminton_coach.cli report --run-dir artifacts/demo --backend template
python -m pytest -q
python -m ruff check .

demo 必须调用真实模块，不另写一套伪造演示。
重复运行使用新 run ID 或显式 overwrite，不毁坏旧结果。

三类验收：
- 工程：管线、解析测试、真实训练、报告与回放正常。
- 研究：授权动作数据下的独立评价支持相应算法结论。
- 产品：真实设备、跨用户与教练标注支持具体功能。

只有解析样例时：
工程可以通过，研究/产品仍为 not_validated。

## 工程架构与产品风险

授权清单→原始动作/原创解析生成→四节点 IMU→同步/校准/六轴融合→BiGRU→合法旋转→FK→相对回放。
并行直接 IMU→确定性证据→程序能力门控→模板/LLM 选择→数值/单位/引用核验。GT 仅进入训练标签和独立 BenchmarkRunner。
采集不足导致不可观测、仿真到真实差异、安装航向歧义、标签不足、数据授权和误诊是核心风险。先验证测量合同、独立用户精度，再验证教练标签支持的具体功能，最后验证成本、佩戴接受度与产品留存。

| 里程碑 | 状态 | 范围 |
|---|---|---|
| M0 授权与数据合同 | implemented / tested | 原创数据与授权清单 fixture；真实授权 blocked_external |
| M1 合成与融合 | implemented / tested | 解析信号、VQF、同步/静止校准 smoke |
| M2 BiGRU 与回放 | implemented / tested | 真实 CPU 训练和独立预测；视觉验收未做 |
| M3 布点与鲁棒性 | implemented / tested | E1–E6 小规模结果；完整研究 not_validated |
| M4 直接特征与证据 | implemented / tested | 描述性测量，未知动作，不输出专项诊断 |
| M5 Agent 受控闭环 | implemented / tested | template/mock/replay；live blocked_external |
| M6 研究评审与交付 | implemented / not_validated | smoke 文档与本地代码交付；研究评审和远程 CI 未通过验证 |
